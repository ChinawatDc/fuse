# fuse (สรุปภาษาไทย)

[![skills.sh](https://skills.sh/b/ChinawatDc/fuse)](https://skills.sh/ChinawatDc/fuse)

**Circuit breaker สำหรับ AI coding agent — สับคัตเอาต์ตัดวงจรก่อน Token ไหลหมดตัว**

เวลาที่ AI เจอบั๊กหรือรัน Test ไม่ผ่าน ปัญหาที่พบบ่อยที่สุดคือ **Agent จะดันทุรังแก้ไฟล์ไปเรื่อยๆ แบบสุ่มสี่สุ่มห้า (Trial-and-error thrashing)** วนซ้ำ 4–5 รอบ กิน Token หลายหมื่น tokens และทำให้โค้ดจุดอื่นพังตามไปด้วย

`fuse` ทำหน้าที่เหมือน **"ฟิวส์ตัดไฟ"**: ตรวจจับความล้มเหลวแบบแบ่งระดับความรุนแรง (3 Tiers) เมื่อถึงขีดจำกัด วงจรจะตัดทันที Agent ต้องหยุดแก้โค้ด บันทึกสิ่งที่เรียนรู้ว่าทำไมถึงล้มเหลว แล้วสรุป 2 ทางเลือกให้มนุษย์ตัดสินใจ

## กลไกการทำงานสำคัญ (v0.2.0)
1. **Dormant Mode (Zero-Overhead):** ขณะโค้ดปกติและเทสผ่าน `fuse` จะสแตนด์บายเงียบๆ ไม่เปลือง Token ใดๆ จะตื่นขึ้นมาทำงานเฉพาะเมื่อคำสั่งมี `Exit Code != 0` หรือเจอ Error
2. **ระบบตัดไฟ 3 ระดับ (3-Tier Thresholds):**
   * **Tier A (Syntax / Typing):** ยอมให้ลองได้สูงสุด **3 ครั้ง** สำหรับเคสลืม import หรือ type เล็กๆ
   * **Tier B (Logic / Test Assertions):** ยึด **2 ครั้ง** อย่างเคร่งครัด ถ้า 2 ครั้งไม่ผ่านแปลว่าสมมติฐานหลักผิด
   * **Tier C (Environment / Infra / Permissions):** **ตัดวงจรทันที (1 ครั้ง)** ถ้าปัญหาอยู่ที่ Database ล่ม, ขาด Env, หรือติดสิทธิ์ OS เพื่อป้องกันไม่ให้ Agent แก้โค้ดมั่ว
3. **Negative Knowledge Ledger (สมุดบันทึกสิ่งที่ล้มเหลว):** บังคับให้ Agent สรุปว่าลองอะไรไปแล้วและทำไมถึงพัง เพื่อไม่ให้วนกลับมาทำวิธีเดิมอีก
4. **Rollback Discipline (ย้อนโค้ดกลับจุดเดิม):** หากวิธีทดลองไม่ผ่าน ให้กดยกเลิก diff นั้นออกไป ไม่วางโค้ดทดลองซ้อนทับกันจนเละ
5. **Structured Escalation (เสนอ 2 ทางเลือกให้คนเคาะ):** เมื่อฟิวส์ตัด Agent จะสรุปสาเหตุที่แท้จริง และยื่น 2 ทางเลือก (เช่น ปรับโครงสร้างระบบ vs ปรับแก้เงื่อนไข Test) ให้ Developer เลือกทางเดินต่อ
